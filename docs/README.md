# Docs

Loose markdown notes, general references, meeting notes, and documentation that doesn't belong in a more specific section.

## Structure

```
docs/
├── notes/             # Informal notes and explorations
├── meetings/          # Meeting notes (YYYY-MM-DD-<topic>.md)
└── guides/            # How-to guides and onboarding material
```

## Conventions

- Prefer placing documentation alongside the code it describes (e.g. a README in the relevant section).
- Use this directory for cross-cutting concerns, general notes, or material not yet assigned to a section.
- Meeting notes follow `YYYY-MM-DD-<topic>.md` naming.
